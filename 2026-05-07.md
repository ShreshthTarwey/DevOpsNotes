# Maven + Docker Integration Practical - May 7, 2026

This document covers the practical session on integrating Maven build tool with Docker containerization, demonstrating how to create a Java application, package it with Maven, and containerize it using Docker.

---

## Overview

This practical demonstrates the integration between Maven (Java build tool) and Docker (containerization platform). The goal is to create a simple Java application, build it with Maven, and then create a Docker image that can run the application in a containerized environment.

### Prerequisites
- Java JDK (version 17 or higher)
- Maven installed and configured
- Docker Desktop installed and running
- Basic knowledge of Java, Maven, and Docker

---

## Step 1: Create Maven Project

**Command:**
```bash
mvn archetype:generate \
  -DgroupId=com.example \
  -DartifactId=docker-demo \
  -DarchetypeArtifactId=maven-archetype-quickstart \
  -DinteractiveMode=false
```

**Explanation:**
- `mvn archetype:generate`: Uses Maven archetype to generate a new project from a template
- `-DgroupId=com.example`: Defines the package structure/group identifier
- `-DartifactId=docker-demo`: Sets the project name
- `-DarchetypeArtifactId=maven-archetype-quickstart`: Uses the quickstart archetype (simple Java project template)
- `-DinteractiveMode=false`: Runs in non-interactive mode (no prompts)

**Result:** Creates a new Maven project with standard directory structure:
```
docker-demo/
├── src/
│   ├── main/java/com/example/App.java
│   └── test/java/com/example/AppTest.java
├── pom.xml
└── README.md
```

## Step 2: Modify Java Program

**File:** `src/main/java/com/example/App.java`

**Content:**
```java
package com.example;

public class App {
    public static void main(String[] args) {
        System.out.println("Hello from Docker + Maven Integration!");
    }
}
```

**Explanation:**
- Simple Java class with main method
- Prints a message to demonstrate the integration
- Note: The artifactId in the command was `docker-demo`, but the pom.xml shows `docker-maven-demo` - this is likely a correction made during the practical

## Step 3: Create Dockerfile

**File:** `Dockerfile` (in project root)

**Content:**
```dockerfile
FROM eclipse-temurin:21-jdk
WORKDIR /app
COPY target/docker-maven-demo-1.0-SNAPSHOT.jar app.jar
ENTRYPOINT ["java","-jar","app.jar"]
```

**Explanation:**
- `FROM eclipse-temurin:21-jdk`: Uses Eclipse Temurin JDK 21 as base image
- `WORKDIR /app`: Sets working directory inside container
- `COPY target/docker-maven-demo-1.0-SNAPSHOT.jar app.jar`: Copies the built JAR file
- `ENTRYPOINT ["java","-jar","app.jar"]`: Defines how to run the application

**Note:** The JAR file name should match what Maven generates (based on artifactId and version).

## Step 4: Add dockerfile-maven-plugin in pom.xml

**File:** `pom.xml`

**Complete Content:**
```xml
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         http://maven.apache.org/xsd/maven-4.0.0.xsd">

    <modelVersion>4.0.0</modelVersion>

    <groupId>com.example</groupId>
    <artifactId>docker-maven-demo</artifactId>
    <version>1.0-SNAPSHOT</version>
    <packaging>jar</packaging>

    <name>docker-maven-demo</name>

    <properties>
        <maven.compiler.source>17</maven.compiler.source>
        <maven.compiler.target>17</maven.compiler.target>
    </properties>

    <dependencies>
        <dependency>
            <groupId>junit</groupId>
            <artifactId>junit</artifactId>
            <version>4.13.2</version>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <build>
        <plugins>

            <!-- JAR Plugin -->
            <plugin>
                <groupId>org.apache.maven.plugins</groupId>
                <artifactId>maven-jar-plugin</artifactId>
                <version>3.3.0</version>
                <configuration>
                    <archive>
                        <manifest>
                            <mainClass>com.example.App</mainClass>
                        </manifest>
                    </archive>
                </configuration>
            </plugin>

            <!-- Docker Plugin -->
            <plugin>
                <groupId>com.spotify</groupId>
                <artifactId>dockerfile-maven-plugin</artifactId>
                <version>1.4.13</version>
                <configuration>
                    <repository>docker-maven-demo</repository>
                    <tag>${project.version}</tag>
                </configuration>
            </plugin>

        </plugins>
    </build>

</project>
```

**Key Components:**

**JAR Plugin Configuration:**
- `maven-jar-plugin`: Creates executable JAR with manifest
- `<mainClass>com.example.App</mainClass>`: Specifies the main class to run

**Docker Plugin Configuration:**
- `dockerfile-maven-plugin`: Integrates Docker build with Maven
- `<repository>docker-maven-demo</repository>`: Docker image name
- `<tag>${project.version}</tag>`: Uses Maven project version as Docker tag

## Step 5: Build JAR File

**Command:**
```bash
mvn clean package
```

**Explanation:**
- `mvn clean`: Removes previous build artifacts
- `mvn package`: Compiles code, runs tests, and packages into JAR
- Result: Creates `target/docker-maven-demo-1.0-SNAPSHOT.jar`

**Expected Output:**
- Compilation success
- Tests pass
- JAR file created in target/ directory

---

## Step 6: Build Docker Image Using Maven

**Command:**
```bash
mvn dockerfile:build
```

**Explanation:**
- Uses the dockerfile-maven-plugin to build Docker image
- Reads Dockerfile from project root
- Tags image as `docker-maven-demo:1.0-SNAPSHOT`

**Process:**
1. Plugin connects to Docker daemon
2. Sends build context to Docker
3. Docker builds image using Dockerfile
4. Image is tagged and stored locally

## Troubleshooting: Docker Daemon Issues

If `mvn dockerfile:build` fails with Docker connection issues:

### Step 1: Open Docker Desktop
- Launch Docker Desktop application

### Step 2: Access Settings
- Go to Settings → General

### Step 3: Enable TCP Daemon
- **Tick the option:** "Expose daemon on tcp://localhost:2375 without TLS"
- This allows Maven plugin to connect to Docker daemon via TCP

### Step 4: Apply & Restart
- Click "Apply & Restart" to restart Docker Desktop

### Step 5: Retry Build
```bash
mvn dockerfile:build
```

**Explanation:**
- By default, Docker daemon only accepts local connections via Unix socket
- Enabling TCP access allows Maven plugin to communicate with Docker
- **Security Note:** This exposes Docker daemon without TLS - use only in development environments

## Complete Workflow Summary

1. **Project Creation:** `mvn archetype:generate` creates Maven project structure
2. **Code Development:** Modify Java source code in `src/main/java/`
3. **Container Definition:** Create Dockerfile for containerization
4. **Build Configuration:** Add Maven plugins in `pom.xml`
5. **JAR Building:** `mvn clean package` creates executable JAR
6. **Image Building:** `mvn dockerfile:build` creates Docker image
7. **Verification:** `docker images` confirms image creation
8. **Execution:** `docker run` executes containerized application

## Key Concepts Demonstrated

### Maven + Docker Integration Benefits
- **Automated Build Pipeline:** Single command builds both JAR and Docker image
- **Consistency:** Same build process across development and production
- **Dependency Management:** Maven handles Java dependencies, Docker handles runtime environment
- **Portability:** Application runs identically in any environment with Docker

### Plugin Architecture
- **maven-jar-plugin:** Creates executable JAR with proper manifest
- **dockerfile-maven-plugin:** Integrates Docker build into Maven lifecycle

### Containerization Advantages
- **Isolation:** Application runs in isolated environment
- **Consistency:** Same runtime environment everywhere
- **Scalability:** Easy to deploy multiple instances

## Common Issues and Solutions

| Issue | Symptom | Solution |
|-------|---------|----------|
| Docker connection failed | Plugin can't connect to Docker daemon | Enable TCP daemon in Docker Desktop settings |
| JAR not found | COPY command fails in Dockerfile | Ensure `mvn clean package` runs before Docker build |
| Main class not found | Container fails to start | Verify `<mainClass>` in pom.xml matches actual class |
| Image build fails | Docker build errors | Check Dockerfile syntax and file paths |

## Best Practices

1. **Version Management:** Use consistent versioning between Maven and Docker tags
2. **Multi-stage Builds:** Consider using multi-stage Dockerfiles for smaller images
3. **Security:** Don't expose Docker daemon in production environments
4. **Layer Optimization:** Order Dockerfile instructions for better layer caching
5. **Testing:** Include integration tests that run the Docker container

## Conclusion

This practical demonstrates a complete CI/CD pipeline component where Maven handles the build and dependency management, while Docker provides the runtime environment. The integration allows developers to build, package, and deploy Java applications consistently across different environments.

The dockerfile-maven-plugin bridges the gap between Maven's build lifecycle and Docker's containerization, enabling automated container image creation as part of the build process.
